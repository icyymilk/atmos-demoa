## 实现思路

围绕「描述需求 → 生成应用 → 可操作预览 → 对话修改」实现一条完整路径。Agent 在每轮自主选择 MCP 工具并读取真实结果，可以检索、编辑、验证和反复修复。交付检查通过后，将代码、工作区文件和执行轨迹原子保存为版本。详细架构见 [Harness 工程说明](HARNESS.md)。

生成的代码在受限 iframe 中执行。宿主提供统一数据接口，让任务、支出等应用数据也能保存在数据库，而不只是保存聊天记录。

## 三分钟体验路线

1. 打开首页，点击「轻量任务看板」模板，无需填写密钥。
2. 在预览中添加任务、改变任务状态；刷新页面确认项目和任务仍保留。
3. 在模型设置中选择服务，填写体验者自己的 Key，点击「测试连接」确认服务可达，再保存配置。
4. 输入「保留现有功能，增加按关键词搜索任务的功能」，查看需求规划与生成进度。
5. 在新预览中验证搜索；切换「代码」查看源码。
6. 打开「版本」，恢复之前的版本；确认历史仍保留，应用数据没有被清空。
7. 点击「导出应用」，用浏览器直接打开 HTML 文件。

前三个模板为明确标注的预置示例；第 4 步是真实模型调用，需要有效密钥。

## 关键取舍

- 单文件原生应用：缩短生成到可运行的链路，避免依赖安装与构建环境的不确定性。
- 显式流程编排：角色清楚、失败边界清楚，不为展示“多智能体”增加无法验证的复杂性。
- 访客会话与 D1：保证真实持久化和项目隔离，优先完成核心创作流程。
- BYOK：体验者选择模型，密钥不落盘，避免公开 Demo 使用共享账户密钥。
- 版本恢复以追加新版本实现：保护历史，并支持随时继续迭代。

继续投入时间时，优先补真实模型回归和浏览器自动修复，再做账户恢复、预览隔离与运行配额，最后扩展多文件工程和独立发布。
